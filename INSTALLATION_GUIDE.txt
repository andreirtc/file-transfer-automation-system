FILE TRANSFER AUTOMATION SYSTEM - INSTALLATION

1. Read docs/IT_HANDOVER.md before company deployment.
2. Use the complete tested release folder, including _internal, templates and docs.
   Place it in a writable location, for example C:\Apps\FileTransferAutomationSystem.
3. Run FileTransferAutomationSystem.exe under the intended Windows account.
   Confirm source read access and destination create/write/replace access.
4. Configure jobs, schedule end-day, operational cycle, transfer mode, verification,
   overwrite policy and corporate checklist mappings. Keep source cleanup disabled
   until IT approves retention. Change the development ZIP password if ZIP is used.
5. Complete docs/DEMO_CHECKLIST.md on the target PC and real network shares.
6. Configure logon startup and keep the PC awake if continuous operation is needed.
   This is a GUI application, not a Windows service. Missed schedule end minutes
   require manual batch recovery.

DATA AND UPGRADES
Close the app and wait for transfers before backing up or upgrading.
Preserve database/transfer_history.db (jobs AND history), config/config.json
(global settings/checklist), reports and logs. Keep any remaining SQLite WAL/SHM
companions with a cold database backup. Do not overwrite the company's config
with a developer's copy. Replace approved executable, _internal, templates and docs.

SOURCE BUILD
setup.bat creates the Python virtual environment and installs requirements.
run_app.bat launches source. build_exe.bat builds a portable Windows release.
A source fix does not change a previously built EXE; rebuild and verify it.

OPERATOR AND SUPPORT GUIDES
The Guide page loads the same documents shipped in docs:
OPERATOR_GUIDE.md, DEMO_CHECKLIST.md, IT_HANDOVER.md and AUDIT_REPORT.md.
Use Logs plus logs/application.log, transfer.log and error.log for diagnosis.
Assign an IT support owner. Copy verification does not guarantee database restore
or maintenance-free operation; company acceptance and restore tests are required.
